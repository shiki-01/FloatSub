# 字幕の遅延計測

音声が端末に届いてから、字幕が表示されるまでの時間を、アプリ内のログで確認するための手順と記録です。

## 計測の仕組み

- 取り込んだ音声を文字起こしへ渡すたびに、「音声の累積秒」と「その時刻（`systemUptime`）」の対応を記録します（`AudioTimeline`）。
- 文字起こし結果は、覆う音声の範囲（`result.range`）を持ちます。範囲の終端にあたる音声を渡した時刻を、上の対応から引き、その時刻を遅延の起点にします。
- 話した時刻そのものは測れません。端末へ音声が届いた時刻が起点です（取り込み側の遅延は含みません）。

| 指標 | 起点 → 終点 |
|---|---|
| 認識（確定） | 確定結果の終端の音声が届いた時刻 → 確定結果を受け取った時刻 |
| 翻訳 | 翻訳の開始 → 翻訳の完了 |
| 字幕（確定訳） | 確定結果の終端の音声が届いた時刻 → 確定訳を字幕へ出した時刻 |
| 字幕（暫定訳） | 途中結果の終端の音声が届いた時刻 → 暫定訳を字幕へ出した時刻（暫定訳を有効にしたときだけ記録） |

## 変更内容（翻訳の高速化）

変更前は、文字起こしが確定した文節だけを翻訳していたため、確定を待つ時間がそのまま字幕の遅れになっていた。変更後は次の 3 点で、確定を待たずに字幕を出す。

- 暫定訳: 話している途中の原文（volatile）を約 0.25 秒間隔で翻訳し、薄く（透明度 50%）表示する。確定結果が届くと確定訳に置き換える。確定した原文が直前に訳した原文と同じなら、翻訳をやり直さずにその訳を確定訳にする。設定の「暫定訳を表示（薄く表示）」で切り替えられる。
- 句読点での分割: 途中結果に文末（`. ? ! 。 ？ ！`）があり、その後ろにさらに文字が続いているとき、文末までを 1 文節として確定扱いにし、すぐ翻訳する。文末がなくても 140 文字を超えたら読点・カンマで区切る。
- 無音での分割: 途中結果が 0.7 秒変わらず、残りが英数字 20 文字以上のとき、残り全体を 1 文節にする。

区切った部分は、あとから届く確定結果から取り除く（重複させない）。区切りの音声時刻は、文字数の比で按分した推定値。

## 見かた

- 詳細欄（「詳細（取り込み方式・診断・ログ）」）の「音声から字幕までの遅延」に、直近 50 件の平均と最大が出ます。
- 同じ欄のログに、確定ごとの値が `遅延 …` の行で出ます。

## 計測手順

1. TestFlight 版で、英語の音声（話者が連続して話す YouTube の動画など）を 2 分以上流す。
2. 詳細欄の「音声から字幕までの遅延」を控える（文字を長押しして選択できる）。
3. 同じ動画の同じ箇所で、変更前のビルドと変更後のビルドを比較する。
